Self-Hosting Website Analytics: Umami vs Matomo vs Plausible in 2026

2026-07-11 · 13 min read · by xbyteid
AnalyticsPrivacySelf-HostingDevOps

Google Analytics is the default for most websites, but it comes with a cost: privacy concerns, cookie consent banners, GDPR headaches, and giving Google even more data about your visitors. In 2026, self-hosted analytics alternatives are mature, lightweight, and easy to deploy. I've tested three of the best — here's what actually works.

The Contenders

  • Umami — Node.js + PostgreSQL/MySQL. Ultra-lightweight script (2KB), real-time dashboard, privacy-first (no cookies, no personal data). My personal choice.
  • Matomo — PHP + MySQL. The most feature-rich alternative. Full Google Analytics replacement with heatmaps, session recordings, A/B testing. Heavier resource usage.
  • Plausible — Elixir + ClickHouse. Beautiful single-page dashboard, <1KB script, EU-hosted option. Open source but the hosted version is paid.

Quick Comparison

  • Script size: Plausible (<1KB) < Umami (2KB) << Matomo (22KB) << GA4 (45KB)
  • Memory usage: Umami (~100MB) < Plausible (~500MB with ClickHouse) < Matomo (~1GB+)
  • Features: Matomo (most) > Umami (good) > Plausible (basic but clean)
  • Setup difficulty: Umami (easiest) < Plausible (moderate) < Matomo (complex)
  • Database: Umami supports PostgreSQL or MySQL. Matomo needs MySQL. Plausible requires ClickHouse (resource-heavy).

Deploying Umami with Docker

Umami is the easiest to self-host. One Docker Compose file and you're running:

# docker-compose.yml
version: '3'
services:
  umami:
    image: ghcr.io/umami-software/umami:postgresql-latest
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgresql://umami:umami@db:5432/umami
      DATABASE_TYPE: postgresql
      APP_SECRET: your-random-secret-here
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: umami
      POSTGRES_USER: umami
      POSTGRES_PASSWORD: umami
    volumes:
      - umami-db:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U umami"]
      interval: 5s
      timeout: 5s
      retries: 5
    restart: unless-stopped

volumes:
  umami-db:

Run: docker compose up -d

Default login: admin / umami. Change the password immediately. Add your website in the dashboard, copy the tracking script, and paste it into your HTML <head>:

<script defer src="https://analytics.yourdomain.com/script.js" data-website-id="your-website-id"></script>

Nginx Reverse Proxy

Put Nginx in front for SSL and a clean domain:

server {{
    listen 443 ssl http2;
    server_name analytics.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/analytics.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/analytics.yourdomain.com/privkey.pem;

    location / {{
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }}
}}

Deploying Plausible

Plausible requires ClickHouse, which uses more memory (~500MB minimum):

# docker-compose.yml
version: '3'
services:
  plausible:
    image: ghcr.io/plausible/community-edition:v2.1
    ports:
      - "8000:8000"
    environment:
      BASE_URL: https://analytics.yourdomain.com
      SECRET_KEY_BASE: your-random-secret-64-chars
      DATABASE_URL: postgres://postgres:postgres@plausible_db:5432/plausible
      CLICKHOUSE_DATABASE_URL: http://plausible_events_db:8123/plausible
    depends_on:
      - plausible_db
      - plausible_events_db
    restart: unless-stopped

  plausible_db:
    image: postgres:15-alpine
    volumes:
      - plausible-db:/var/lib/postgresql/data
    environment:
      POSTGRES_PASSWORD: postgres
    restart: unless-stopped

  plausible_events_db:
    image: clickhouse/clickhouse-server:24.3-alpine
    volumes:
      - event-data:/var/lib/clickhouse
      - event-logs:/var/log/clickhouse-server
    restart: unless-stopped

volumes:
  plausible-db:
  event-data:
  event-logs:

Deploying Matomo

Matomo is PHP-based, needs MySQL, and uses more resources. But it's the most feature-complete:

# docker-compose.yml
version: '3'
services:
  matomo:
    image: matomo:latest
    ports:
      - "8080:80"
    volumes:
      - matomo-data:/var/www/html
    environment:
      MATOMO_DATABASE_HOST: matomo-db
      MATOMO_DATABASE_ADAPTER: mysql
      MATOMO_DATABASE_TABLES_PREFIX: matomo_
      MATOMO_DATABASE_USERNAME: matomo
      MATOMO_DATABASE_PASSWORD: matomo
      MATOMO_DATABASE_DBNAME: matomo
    depends_on:
      - matomo-db
    restart: unless-stopped

  matomo-db:
    image: mysql:8
    environment:
      MYSQL_DATABASE: matomo
      MYSQL_USER: matomo
      MYSQL_PASSWORD: matomo
      MYSQL_ROOT_PASSWORD: rootpass
    volumes:
      - matomo-db:/var/lib/mysql
    restart: unless-stopped

volumes:
  matomo-data:
  matomo-db:

My Setup: Umami on a $5 VPS

I run Umami on the same VPS as my other tools. It uses about 100MB of RAM and handles traffic from multiple websites without breaking a sweat. The dashboard is fast, the data is accurate, and I don't need to worry about cookie consent banners or GDPR compliance.

Key configuration I use:

  • PostgreSQL over MySQL — better for concurrent writes
  • Nginx reverse proxy with SSL via Let's Encrypt
  • Systemd service for auto-restart on crash
  • Backup — daily pg_dump to a separate directory

Tracking Script Placement

Where you put the tracking script matters. Always place it in the <head> section, not at the bottom of <body>. This ensures it captures page views even if the user navigates away before the full page loads:

<head>
  <!-- other head content -->
  <script defer src="https://analytics.yourdomain.com/script.js" 
          data-website-id="abc-123"></script>
</head>

The defer attribute ensures it doesn't block page rendering.

Pro tip: If you're migrating from Google Analytics, keep both scripts running for 2-4 weeks to compare numbers. Umami/Plausible typically show 10-20% fewer pageviews than GA because they don't count bots and don't use cookies (so returning visitors aren't double-counted). This is actually more accurate.

When to Choose Each

  • Umami: You want something simple, lightweight, and easy to maintain. Perfect for personal sites, portfolios, small businesses. Runs on minimal resources.
  • Plausible: You want the cleanest dashboard and don't mind the higher memory usage from ClickHouse. Good for marketing-focused sites that need UTM tracking.
  • Matomo: You need full GA replacement — heatmaps, session recordings, A/B testing, custom dimensions, e-commerce tracking. Worth the extra complexity for large sites.

For most developers self-hosting analytics, Umami is the sweet spot — simple enough to set up in 5 minutes, powerful enough for real-world use, and light enough to run alongside your other services on a cheap VPS.
