Python Automation Scripts Every Developer Should Know in 2026

Why Python for Automation

Python's standard library covers file I/O, HTTP, email, scheduling, and JSON out of the box. No dependencies needed for 80% of automation tasks. When you do need extras, requests, beautifulsoup4, and schedule are single pip install away. This guide covers scripts you'll actually use -- not toy examples, but the patterns that save hours every week in real development workflows.

File Management with pathlib

The pathlib module is the modern way to handle file operations. It replaces os.path, glob, and shutil for most tasks with a clean, chainable API:

from pathlib import Path
import shutil

# Find all PDFs recursively
pdfs = list(Path("documents").rglob("*.pdf"))

# Organize files by extension
for f in Path("downloads").iterdir():
    if f.is_file():
        dest = Path("organized") / f.suffix[1:]
        dest.mkdir(parents=True, exist_ok=True)
        shutil.move(str(f), str(dest / f.name))

# Batch rename with pattern
for i, f in enumerate(sorted(Path("photos").glob("*.jpg"))):
    f.rename(f.parent / f"photo_{i:04d}.jpg")

Real-World File Automation

Clean up a messy project directory by removing common build artifacts:

from pathlib import Path
import shutil

def clean_project(root):
    """Remove build artifacts, caches, and temp files."""
    patterns = [
        "__pycache__", ".pytest_cache", ".mypy_cache",
        "node_modules", ".next", "dist", "build",
        "*.pyc", ".DS_Store", "Thumbs.db",
    ]
    removed = 0
    for pattern in patterns:
        for path in root.rglob(pattern):
            if path.is_dir():
                shutil.rmtree(path)
            else:
                path.unlink()
            removed += 1
            print(f"Removed: {path.relative_to(root)}")
    print(f"Cleaned {removed} items from {root}")

clean_project(Path("."))

Watching for File Changes

Monitor directories for changes using watchdog:

from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler
import time

class ChangeHandler(FileSystemEventHandler):
    def on_modified(self, event):
        if event.src_path.endswith('.py'):
            print(f"Modified: {event.src_path}")

    def on_created(self, event):
        print(f"Created: {event.src_path}")

observer = Observer()
observer.schedule(ChangeHandler(), path="./src", recursive=True)
observer.start()

try:
    while True:
        time.sleep(1)
except KeyboardInterrupt:
    observer.stop()
observer.join()

Web Scraping with requests + BeautifulSoup

For static pages, requests + BeautifulSoup is fast and simple:

import requests
from bs4 import BeautifulSoup

def scrape_articles(url):
    resp = requests.get(url, headers={"User-Agent": "Mozilla/5.0"})
    soup = BeautifulSoup(resp.text, "html.parser")

    articles = []
    for item in soup.select("article.post"):
        title = item.select_one("h2").get_text(strip=True)
        link = item.select_one("a")["href"]
        date = item.select_one("time")["datetime"]
        articles.append({"title": title, "url": link, "date": date})

    return articles

Handling Pagination and Rate Limiting

Real scraping needs pagination and politeness:

import requests
from bs4 import BeautifulSoup
from time import sleep
import random

def scrape_all_pages(base_url, max_pages=10):
    all_items = []
    for page in range(1, max_pages + 1):
        url = f"{base_url}?page={page}"
        resp = requests.get(url, headers={"User-Agent": "Mozilla/5.0"})

        if resp.status_code != 200:
            break

        soup = BeautifulSoup(resp.text, "html.parser")
        items = soup.select(".item")

        if not items:
            break  # No more results

        for item in items:
            all_items.append({
                "title": item.select_one("h3").get_text(strip=True),
                "link": item.select_one("a")["href"],
            })

        # Be polite -- random delay between requests
        sleep(random.uniform(1.0, 3.0))
        print(f"Page {page}: {len(items)} items")

    return all_items

Dynamic Pages with Playwright

For JavaScript-heavy sites, use Playwright for browser automation:

from playwright.sync_api import sync_playwright

def scrape_dynamic(url):
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        page.goto(url)

        # Wait for content to load
        page.wait_for_selector(".results")

        items = page.query_selector_all(".result-item")
        results = []
        for item in items:
            results.append({
                "title": item.query_selector("h3").inner_text(),
                "url": item.query_selector("a").get_attribute("href"),
            })

        browser.close()
        return results

API Integration

Automate API calls with proper error handling and retries:

import requests
from time import sleep

class APIClient:
    def __init__(self, base_url, api_key):
        self.base_url = base_url
        self.session = requests.Session()
        self.session.headers["Authorization"] = f"Bearer {api_key}"

    def get(self, endpoint, retries=3):
        for attempt in range(retries):
            try:
                resp = self.session.get(f"{self.base_url}{endpoint}")
                resp.raise_for_status()
                return resp.json()
            except requests.RequestException as e:
                if attempt == retries - 1:
                    raise
                sleep(2 ** attempt)  # exponential backoff

# Usage
api = APIClient("https://api.example.com", "your-key")
data = api.get("/v1/users")

Paginated API Consumption

Handle paginated APIs with a generator -- memory-efficient for large datasets:

def fetch_all_pages(client, endpoint, page_size=100):
    """Generator that yields items from a paginated API."""
    page = 1
    while True:
        data = client.get(f"{endpoint}?page={page}&per_page={page_size}")
        if not data["results"]:
            break
        yield from data["results"]
        page += 1

# Usage -- processes one page at a time
for user in fetch_all_pages(api, "/v1/users"):
    process_user(user)

Webhook Receiver

Receive and process webhooks with a minimal Flask server:

from flask import Flask, request, jsonify
import hmac, hashlib

app = Flask(__name__)
WEBHOOK_SECRET = "your-webhook-secret"

@app.route("/webhook", methods=["POST"])
def handle_webhook():
    # Verify signature
    signature = request.headers.get("X-Signature-256")
    expected = hmac.new(
        WEBHOOK_SECRET.encode(),
        request.data,
        hashlib.sha256
    ).hexdigest()

    if not hmac.compare_digest(signature, expected):
        return jsonify({"error": "Invalid signature"}), 401

    payload = request.json
    print(f"Received: {payload['event']}")
    return jsonify({"status": "ok"}), 200

Scheduled Tasks with APScheduler

Run jobs on a schedule without cron:

from apscheduler.schedulers.blocking import BlockingScheduler

scheduler = BlockingScheduler()

@scheduler.scheduled_job('cron', hour=9, minute=0)
def daily_report():
    data = fetch_daily_metrics()
    send_slack_notification(format_report(data))

@scheduler.scheduled_job('interval', minutes=30)
def check_health():
    status = ping_services()
    if any(s != 200 for s in status.values()):
        alert_on_call(status)

scheduler.start()

Why APScheduler Over Cron

  • Portable -- works on Windows, macOS, Linux without platform-specific cron syntax
  • Persistent -- with a job store (Redis, SQLAlchemy), jobs survive restarts
  • Dynamic -- add/remove/modify jobs at runtime via API
  • Testable -- run scheduler in a thread during tests

For simple scripts that run on Linux, cron is fine. For anything that needs portability, persistence, or dynamic scheduling, APScheduler is the better choice.

Email Automation with smtplib

Send emails programmatically for alerts and reports:

import smtplib
from email.mime.multipart import MIMEMultipart
from email.mime.text import MIMEText

def send_email(to, subject, html_body):
    msg = MIMEMultipart("alternative")
    msg["From"] = "alerts@yourdomain.com"
    msg["To"] = to
    msg["Subject"] = subject
    msg.attach(MIMEText(html_body, "html"))

    with smtplib.SMTP("smtp.gmail.com", 587) as server:
        server.starttls()
        server.login("user@gmail.com", "app-password")
        server.send_message(msg)

HTML Email Templates

Generate formatted reports with inline CSS (most email clients don't support external stylesheets):

from string import Template

EMAIL_TEMPLATE = Template("""
<html>
<body style="font-family: Arial, sans-serif; max-width: 600px;">
  <h2 style="color: #333;">Daily Report - $date</h2>
  <table style="width: 100%; border-collapse: collapse;">
    <tr style="background: #f4f4f4;">
      <th style="padding: 8px; text-align: left;">Metric</th>
      <th style="padding: 8px; text-align: right;">Value</th>
    </tr>
    $rows
  </table>
</body>
</html>
""")

def format_report(metrics, date):
    rows = "".join(
        f'<tr><td style="padding:8px">{k}</td>'
        f'<td style="padding:8px;text-align:right">{v}</td></tr>'
        for k, v in metrics.items()
    )
    return EMAIL_TEMPLATE.substitute(date=date, rows=rows)

Database Automation

Automate database operations — backups, migrations, data exports — with Python:

import subprocess
from datetime import datetime
from pathlib import Path

def backup_postgres(db_name, output_dir="backups"):
    """Automated PostgreSQL backup with rotation."""
    Path(output_dir).mkdir(exist_ok=True)
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    filename = f"{output_dir}/{db_name}_{timestamp}.sql.gz"

    cmd = f"pg_dump {db_name} | gzip > {filename}"
    subprocess.run(cmd, shell=True, check=True)

    # Keep only last 7 backups
    backups = sorted(Path(output_dir).glob(f"{db_name}_*.sql.gz"))
    for old in backups[:-7]:
        old.unlink()
        print(f"Removed old backup: {old}")

    print(f"Backup created: {filename}")
    return filename

Error Handling Patterns

Production automation scripts need robust error handling. Don't let one failure crash the entire pipeline:

import logging

def run_pipeline(tasks):
    """Run tasks, collecting results without stopping on failure."""
    results = []
    for task_name, task_fn in tasks:
        try:
            task_fn()
            results.append({"name": task_name, "ok": True})
            logging.info(f"Task {task_name} completed")
        except Exception as e:
            results.append({"name": task_name, "ok": False, "error": str(e)})
            logging.error(f"Task {task_name} failed: {e}")

    failed = [r for r in results if not r["ok"]]
    if failed:
        send_alert(f"{len(failed)} tasks failed")
    return results

Task Queue with Celery

For heavy workloads that shouldn't block HTTP requests, use Celery with Redis as a broker:

from celery import Celery

app = Celery("tasks", broker="redis://localhost:6379/0")

@app.task(bind=True, max_retries=3)
def process_upload(self, file_path):
    try:
        result = heavy_processing(file_path)
        send_notification(f"Upload processed: {result}")
        return result
    except Exception as exc:
        self.retry(exc=exc, countdown=60)

# In your Flask/FastAPI handler:
@app.post("/upload")
async def upload(file: UploadFile):
    path = save_to_disk(file)
    process_upload.delay(path)  # non-blocking
    return {"status": "processing"}

Celery handles retries, task chaining, rate limiting, and scheduled tasks. It's production-proven at companies like Instagram, Mozilla, and Robinhood. For simpler use cases, Python's built-in threading or asyncio may be sufficient — don't add Celery until you need distributed task processing.

CLI Tools with Click

Turn your automation scripts into proper CLI tools with click:

import click

@click.group()

    pass

@cli.command()
@click.argument("directory", default=".")
@click.option("--dry-run", is_flag=True, help="Preview changes without applying")
def clean(directory, dry_run):

    else:
        for a in artifacts:

            print(f"Removed: {a}")

@cli.command()
@click.option("--env", default="staging", help="Target environment")

Install your tool globally with pip install -e . and run mytool clean --dry-run or mytool deploy --env production. Click handles help text, argument parsing, and validation automatically.

Pro tip: Use python-dotenv to load API keys and credentials from .env files. Never hardcode secrets in scripts. Add .env to .gitignore immediately.

Running Scripts in Production

For scripts that run on a server, wrap them with proper error handling and logging:

import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s",
    handlers=[
        logging.FileHandler("automation.log"),
        logging.StreamHandler(),
    ]
)
logger = logging.getLogger(__name__)

def main():
    try:
        logger.info("Starting daily price monitor")
        daily_price_monitor()
        logger.info("Completed successfully")
    except Exception as e:
        logger.exception(f"Failed: {e}")
        send_email("admin@company.com", "Pipeline Failed", str(e))

if __name__ == "__main__":
    main()
