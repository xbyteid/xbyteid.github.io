How to Build an EVM Blockchain Monitor with Python

2026-07-11 · 15 min read · by xbyteid
Web3PythonBlockchainEVMAutomation

Monitoring EVM chains used to require expensive node infrastructure and complex indexing. In 2026, free public RPCs like drpc.org and libraries like web3.py make it possible to build a multi-chain monitor on a $5 VPS. I built one that watches 15 chains simultaneously for token transfers, contract events, and gas anomalies — here's the architecture.

Why Monitor On-Chain?

Whether you're tracking whale wallets, monitoring DeFi positions, or watching for suspicious contract activity, on-chain monitoring gives you real-time visibility. Common use cases:

  • Whale tracking — monitor large transfers to/from known addresses
  • DeFi health — watch collateral ratios, liquidation thresholds
  • Contract events — track approvals, swaps, mints, burns
  • Gas monitoring — alert when gas drops below threshold for batch operations
  • New token detection — catch new pair creation events on DEXes

Choosing an RPC Provider

Not all RPCs are equal. Here's what matters:

  • drpc.org — best free option. Supports 15+ chains, batch requests up to 1000 addresses, 50 concurrent connections, no API key needed. 30-60ms latency.
  • publicnode.com — reliable, but batch limit is 3-10 requests. Good as a fallback.
  • Chain-specific RPCs — e.g., rpc.mainnet.chain.robinhood.com for Robinhood Chain. Often rate-limited, but necessary for chains not on drpc.

A critical lesson: always set a User-Agent header. Some RPCs (like Robinhood's) return 403 for default Python urllib requests. And use Accept-Encoding: gzip — not br (brotli decompression has a bug in aiohttp on Python 3.12).

import aiohttp

HEADERS = {{
    "Content-Type": "application/json",
    "User-Agent": "evm-monitor/1.0",
    "Accept-Encoding": "gzip"
}}

RPC_URLS = {{
    1: "https://eth.drpc.org",
    56: "https://bsc.drpc.org",
    137: "https://polygon.drpc.org",
    42161: "https://arbitrum.drpc.org",
    8453: "https://base.drpc.org",
    4663: "https://rpc.mainnet.chain.robinhood.com",
}}

Batch Balance Checking

The power of drpc.org is batch requests. Instead of 1000 individual calls, send one JSON-RPC array:

async def batch_get_balances(rpc_url, addresses):
    """Check balances for up to 1000 addresses in one request."""
    batch = [
        {{
            "jsonrpc": "2.0",
            "id": i,
            "method": "eth_getBalance",
            "params": [addr, "latest"]
        }}
        for i, addr in enumerate(addresses)
    ]
    
    async with aiohttp.ClientSession(headers=HEADERS) as session:
        async with session.post(rpc_url, json=batch) as resp:
            results = await resp.json()
    
    balances = {{}}
    for r in results:
        idx = r["id"]
        addr = addresses[idx]
        bal = int(r["result"], 16) / 1e18
        balances[addr] = bal
    
    return balances

This checks 1000 wallets in a single HTTP request. At 50 concurrent batches, that's 50,000 wallets per second per chain.

Event Log Monitoring

For real-time event monitoring, use eth_getLogs with topic filters:

async def get_transfer_events(rpc_url, contract_address, from_block, to_block):
    """Get all Transfer events from a contract."""
    params = {{
        "fromBlock": hex(from_block),
        "toBlock": hex(to_block),
        "address": contract_address,
        "topics": [
            "0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef"  # Transfer(address,address,uint256)
        ]
    }}
    
    async with aiohttp.ClientSession(headers=HEADERS) as session:
        async with session.post(rpc_url, json={{
            "jsonrpc": "2.0",
            "id": 1,
            "method": "eth_getLogs",
            "params": [params]
        }}) as resp:
            data = await resp.json()
    
    events = []
    for log in data.get("result", []):
        from_addr = "0x" + log["topics"][1][-40:]
        to_addr = "0x" + log["topics"][2][-40:]
        value = int(log["data"], 16)
        events.append({{
            "from": from_addr,
            "to": to_addr,
            "value": value,
            "tx": log["transactionHash"],
            "block": int(log["blockNumber"], 16)
        }})
    return events

Multi-Chain Architecture

Run monitors for multiple chains in parallel with asyncio:

import asyncio

async def monitor_chain(chain_id, rpc_url, watch_list):
    """Monitor a single chain for activity."""
    last_block = await get_latest_block(rpc_url)
    
    while True:
        try:
            current_block = await get_latest_block(rpc_url)
            if current_block > last_block:
                # Process new blocks
                for addr in watch_list:
                    events = await get_transfer_events(
                        rpc_url, addr, last_block + 1, current_block
                    )
                    for event in events:
                        await process_event(chain_id, event)
                last_block = current_block
            
            await asyncio.sleep(2)  # Poll interval
        except Exception as e:
            logging.error(f"Chain {{chain_id}} error: {{e}}")
            await asyncio.sleep(10)

async def main():
    tasks = []
    for chain_id, rpc_url in RPC_URLS.items():
        watch = WATCH_LISTS.get(chain_id, [])
        tasks.append(monitor_chain(chain_id, rpc_url, watch))
    await asyncio.gather(*tasks)

Block Scanning Optimization

Don't scan every block individually. Use range queries and batch them:

async def scan_block_range(rpc_url, from_block, to_block, addresses):
    """Scan a range of blocks for activity across multiple addresses."""
    # Build batch of eth_getLogs calls
    batch = []
    for i, addr in enumerate(addresses):
        batch.append({{
            "jsonrpc": "2.0",
            "id": i,
            "method": "eth_getLogs",
            "params": [{{
                "fromBlock": hex(from_block),
                "toBlock": hex(to_block),
                "address": addr
            }}]
        }})
    
    # Split into chunks of 500 (drpc batch limit)
    all_results = []
    for chunk in chunked(batch, 500):
        async with aiohttp.ClientSession(headers=HEADERS) as session:
            async with session.post(rpc_url, json=chunk) as resp:
                results = await resp.json()
                all_results.extend(results)
    
    return all_results

Storage and Indexing

For a simple monitor, SQLite is enough. For production, use PostgreSQL with proper indexing:

import sqlite3

def init_db():
    conn = sqlite3.connect("monitor.db")
    conn.execute("""
        CREATE TABLE IF NOT EXISTS events (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            chain_id INTEGER,
            contract TEXT,
            from_addr TEXT,
            to_addr TEXT,
            value REAL,
            tx_hash TEXT,
            block_number INTEGER,
            timestamp INTEGER,
            created_at DEFAULT CURRENT_TIMESTAMP
        )
    """)
    conn.execute("CREATE INDEX idx_contract ON events(contract)")
    conn.execute("CREATE INDEX idx_block ON events(block_number)")
    conn.execute("CREATE INDEX idx_from ON events(from_addr)")
    conn.execute("CREATE INDEX idx_to ON events(to_addr)")
    return conn
Pro tip: When monitoring many addresses across many chains, the bottleneck is always network I/O, not CPU. Use aiohttp with connection pooling (TCPConnector(limit=50)) and always use batch RPC calls. A single VPS can monitor 15+ chains simultaneously if you optimize the network layer.

What I've Learned

  • drpc.org is king — free, fast, supports batch on all chains. Public RPCs are backup only.
  • Rate limits vary wildly — Robinhood Chain's native RPC blocks batch >1 request. Always test limits.
  • Block finality matters — don't alert on recent blocks (reorgs happen). Wait 12+ confirmations on Ethereum, 3+ on L2s.
  • Log every RPC call — when debugging, you need to see raw request/response pairs.
  • Use hex carefully — int(log["blockNumber"], 16) converts hex block numbers to int. Easy to forget.
