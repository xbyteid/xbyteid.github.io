Free VPS Guide 2026: Azure, Tencent, Oracle Cloud Free Tier Compared

2026-07-11 · 13 min read · by xbyteid
CloudVPSDevOpsFree Tier

Paying for a VPS when you're starting out is unnecessary. In 2026, major cloud providers offer generous free tiers that let you run real workloads — bots, APIs, analytics, monitoring — without spending a cent. I currently run 6 free VMs across 3 providers. Here's what's actually available and what you can realistically do with them.

The Big Three Free Tiers

Azure for Students

  • Credit: $100 for 12 months (renewable with valid student email)
  • Free VMs: B2ats_v2 (2 vCPU, 1GB RAM) in select regions
  • Best for: x86 workloads, Windows Server if needed
  • Catch: Credit expires in 12 months, VM availability varies by region

Azure for Students doesn't require a credit card — just a valid .edu email or student verification. The $100 credit covers VM costs, but some services (like VPN Gateways) eat credit fast. Stick to free-tier VMs and free services (AI Search, Event Grid, Logic Apps) to maximize value.

Tencent Cloud Free Tier

  • Specs: 2 vCPU Xeon, 2GB RAM, 30GB SSD
  • Region: Singapore, Hong Kong, or China (requires real-name verification for China)
  • Best for: Southeast Asia latency, heavier workloads
  • Catch: Limited availability, apply early. Re-apply after expiry.

Tencent's free tier is the most generous in terms of specs — 2GB RAM makes a huge difference when running Docker containers. The application process can be competitive; they open slots periodically and they fill up fast.

Oracle Cloud Free Tier (Always Free)

  • ARM: Up to 4 OCPUs, 24GB RAM (Ampere A1) — the most generous free VM anywhere
  • x86: 1/8 OCPU, 1GB RAM (E4/E5)
  • Always Free: VMs persist indefinitely, not time-limited
  • Catch: ARM instances are hard to provision (capacity issues), SSH key setup is picky

Oracle's ARM tier is theoretically the best free VM in cloud computing. 24GB RAM for free is insane. In practice, ARM capacity is almost always "out of stock" in popular regions. Try less popular regions (Mumbai, São Paulo) and off-peak hours.

What Can You Actually Run?

On a 2-core, 0.5-2GB RAM VM, here's what I run simultaneously:

  • Telegram bot — Python, webhook mode, ~50MB RAM
  • Umami analytics — Node.js + PostgreSQL, ~100MB RAM
  • Nginx reverse proxy — SSL termination, ~10MB RAM
  • Cron jobs — monitoring scripts, backups, data collection
  • Simple API — FastAPI or Express, ~50MB RAM
  • SQLite database — for small-scale data storage

Total: ~300-400MB RAM. Fits comfortably on a 1GB VM with room to spare. If you need Docker, 2GB is the minimum comfortable size.

Initial Server Setup

The moment you get SSH access, harden the server:

# 1. Update everything
sudo apt update && sudo apt upgrade -y

# 2. Create non-root user
sudo adduser deploy
sudo usermod -aG sudo deploy

# 3. SSH key authentication (disable password)
mkdir -p /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys

# 4. Harden SSH
sudo nano /etc/ssh/sshd_config
# Set: PasswordAuthentication no
# Set: PermitRootLogin no
# Set: Port 2222 (or custom)
sudo systemctl restart sshd

# 5. Firewall
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 2222/tcp   # SSH
sudo ufw allow 80/tcp     # HTTP
sudo ufw allow 443/tcp    # HTTPS
sudo ufw enable

# 6. Fail2ban
sudo apt install fail2ban -y
sudo systemctl enable fail2ban

Essential Monitoring

Set up basic monitoring so you know when things break:

# Simple disk space monitor (add to crontab)
#!/bin/bash
USAGE=$(df / | tail -1 | awk '{print $5}' | tr -d '%')
if [ $USAGE -gt 80 ]; then
    echo "WARNING: Disk usage at ${USAGE}%"
    # Send alert via Telegram, email, etc.
fi

# Memory monitor
#!/bin/bash
FREE_MB=$(free -m | awk '/^Mem:/{print $7}')
if [ $FREE_MB -lt 100 ]; then
    echo "WARNING: Only ${FREE_MB}MB available memory"
fi

Systemd Services

Never use nohup, screen, or tmux for production processes. Systemd handles restarts, logging, and boot persistence:

# /etc/systemd/system/myapp.service
[Unit]
Description=My Application
After=network.target

[Service]
Type=simple
User=deploy
WorkingDirectory=/opt/myapp
ExecStart=/opt/myapp/venv/bin/python main.py
Restart=always
RestartSec=5
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
sudo journalctl -u myapp -f  # View logs

Swap Space

On VMs with less than 2GB RAM, add swap to prevent OOM kills:

# Create 1GB swap file
sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Make permanent
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Tune swappiness (lower = prefer RAM)
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

Tips from Experience

  • Apply early — free tier slots are limited. Apply on day one of availability.
  • Use ARM when available — ARM VMs (Azure B2pts, Oracle A1) are often less contested than x86.
  • Don't store data you can't lose — free VMs can be reclaimed. Always have backups elsewhere.
  • Monitor your credit — Azure credit burns fast if you accidentally use paid services. Set spending alerts.
  • Multiple regions — if B2ats is out of stock in Southeast Asia, try Korea Central or Japan East.
  • Schedule snapshots — take VM snapshots before experimenting. Restore in seconds if something breaks.
Pro tip: Combine free tiers from multiple providers to build a distributed infrastructure. Run your main app on Tencent (2GB RAM), analytics on Azure (1GB), and a backup/cron server on Oracle ARM (24GB if you can get it). Total cost: $0/month. I run 3 VPS from different providers with a combined 6 cores and 4GB RAM for free.

What NOT to Run on Free Tier

  • High-traffic web apps — 0.5-1GB RAM won't handle concurrent users well
  • Database-heavy workloads — PostgreSQL/MySQL need more RAM than free tiers offer
  • Video processing / ML — no GPU, limited CPU
  • Anything with SLA requirements — free VMs can be preempted or reclaimed

Free tiers are perfect for: bots, monitoring, analytics, simple APIs, cron jobs, development/staging, and learning. For production apps with real traffic, upgrade to a paid VPS ($5-20/month gives you 2-4GB RAM and reliable uptime).
